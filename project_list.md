# CMSC 701 Spring 2025 Final Project Idea List

This is a list of suggested final project topics.  This list is not comprehensive, in that you are welcome to propose your own topics, as long as they are approved by me (requires your submission of a 1/2 to 1 page writeup on what project you propose and why it's relevant to genomics). The projects should be done in groups of **2 students**. 

### 1) sparse suffix array based on sampling sketches

Motivation: We discussed the suffix array in the class, which is a mainstay of full-text indexing data structures.  The main shortcoming of the suffix array is its size.  Yet, for the purposes of tasks like read mapping (especially for longer reads), it's likely not necessary to have indexed the position of *every* suffix.  Indeed, sparse variants of the suffix array exist that retain only a (usually regularly sampled) collection of offsets in the original text.  This project seeks to combine the idea of suffix array sampling with the notion of [minimizers](https://academic.oup.com/bioinformatics/article/20/18/3363/202143), which has been fruitful in helping to select consistent, sparse and informative sets of k-mers.

Project: Implement a sparse, sampled suffix array where, instead of performing a regular sampling of the initial suffixes, you instead select which suffixes to retain based on which suffixes represent the start of minimizer sequences.  This data structure will have a size and density dictated by the particular minimizer scheme used and parameters selected, and will allow you to quickly look up any minimizers that occur in the reference string.  You should implement this scheme generally, and explore different minimizer definitions (e.g. lexicographic, hash-based, and other schemes) as well as different parameters for the window length and minimizer size.  You should also evaluate the speed of lookup in this data structure, and potentially with auxiliary data structures (e.g. short prefix tables).  Time permitting, perhaps try to evaluate this data structure in the context of read alignment, or build a small read mapper based around it.

### 2) space-transformed suffix array

**Motivation**: We discussed the suffix array in the class, which is a mainstay of full-text indexing data structures.  The main shortcoming of the suffix array is its size.  Yet, for the purposes of tasks like read mapping (especially for longer reads), it's likely not necessary to have indexed all suffixes exactly.  This project is motivated by recent work such as the [minimizer space de Bruijn graphs](https://pubmed.ncbi.nlm.nih.gov/34525345/). If successful this would lead to smaller index capable of matching chains of minimizers using a suffix array like data structure, which could be useful for large-scale sequence comparison, long read mapping, and potentially other tasks.

**Project**:  Here the main idea is to perform a *transformation* of the original genome — to parse the genome as a sequence of tokens (e.g. minimizers, syncmers, or some other type of sketch) — and build the suffix array on this transformed sequence rather than the original genome.  While sharing some concepts with the samples suffix array, this one is different. Now, given a query, one no longer considers querying in the original alphabet. Rather, one transforms their query into a sequence of tokens as well and the queries the suffix array with this transformed query.  The potential benefit of this is that, though the *alphabet* of the reference and query are much larger (equal to the number of distinct tokens), the lengths of the reference and query are now *much* shorter.  For example, queries that may initially consist of hundreds of bases may reduce to only a dozen or so tokens.  You should experiment with different tokenization definitions and parameters.  Likewise, it is possible that basic learned index schemes could work very well with an approach like this (e.g. ideas like [sapling](https://academic.oup.com/bioinformatics/article/37/6/744/5941464) and [pla search](https://drops.dagstuhl.de/storage/00lipics/lipics-vol312-wabi2024/LIPIcs.WABI.2024.13/LIPIcs.WABI.2024.13.pdf)).  If you have time once you've implemented and tested the initial tokenized suffix array, you should explore techniques like this to further accelerate the search.


### 3) Squeezing single-cell data : 

Motivation: Single-cell RNA-sequencing data is being generated at an incredible pace.  High throughput technologies allow the sequencing and quantification of genes in 10s of thousands of cells in a typical experiment, and experimental multiplexing technologies make it possible to assay 100s of thousands of cell in a single experiment.  Yet, this produces not just a massive amount of sequencing data, but even the *output* of the initial processing — big, sparse, and "wide" count matrices — can grow very large and require a lot of space to store both on disk, and to access in memory.
    
Goal: Develop an efficient format for single-cell count matrices (initially focused on single-cell RNA-seq) that reduces the requirements compared to existing formats.  There are many ideas to apply here, but one can think about making use of succinct data structures as well as making use of delta encoding; many cells in a dataset will have an expression profile similar to that of other cells.  So, rather than encoding each cell's expression independently, can we encode it with respect to some neighboring cell? Your representation can be geared toward storage, efficient in-memory representation, or both. The input to your algorithm is a sparse $N \times M$ matrix, and the output is a representation that can be efficiently stored on disk, retrieved over the network, and decompressed for subsequent analysis.  We are interested in both lossless and lossy (but controlled) compression.  That is, if the compression is lossy, we should demonstrate that it doesn't degrade the downstream analyses that people do with such data (e.g. dimensionality reduction, clustering, pseudotime analysis, etc.).  The compression method you develop should be compared with compression techniques that are standard within this space, including encoding the matrix in standard CSR (compressed sparse row), CSC (compressed sparse column), and MTX (matrix market) formats, including standard "gzipped" versions of these formats.  You should also compare with the popular "loom" format, which uses HDF5 as the compression backend.

### 5) Reducing the space of hash-based k-mer indices by better encoding of inverted lists

There has recently been several hash-based indices proposed for building a map / associative container over k-mers.  Our lab initially built the pufferfish index (which we will talk about in class), but subsequently the blight and SSHash indices were introduced.  Recently, we have teamed up with the author of SSHash and developed an improved index that pairs SSHash with a unitig-to-occurrence mapping to yield a complete reference index.

As larger reference collections are indexed, the component of the index that comes to dominate the overall size is the "unitig-to-occurrence" map — essentially an inverted index mapping each unitig to its list of occurrences in the references.  We recently introduced a sampling-based scheme to compress this map in a paper that will appear at RECOMB this year ([here](https://www.biorxiv.org/content/10.1101/2022.10.27.513881v2)).  However, this scheme is quite sophisticated, and obtains small space usage at the cost of a substantially increased constant factor in decoding unitig occurrences.

The goal of this project is to explore alternative methods for compressing these inverted indices (including methods that are commonly used in the general inverted indexing literature).  Are there non-sampling based schemes that compress these inverted lists in a manner that might offer similar space benefits but faster decoding?  What properties of inverted lists enable efficient compression?  Presumably short lists won't benefit from such schemes, but how long does a list need to be before it does?  Are there other schemes for compressing these inverted lists that you can think about and test?

While eventually a well-performing method would be integrated into a full index, this project is focused only on compression of the unitig-to-occurrence table and so the focus, development, and evaluation can be safely restricted to just the relevant queries in this table.

### 7) Finding better seeds for sequence alignment

We have spent a lot of time in the class discussing k-mers, and we are also discussing their extensive use in indexing for the purposes of mapping reads.  While k-mers are great for many reasons, they are but one of many types of seeds.  Spaced k-mers (spaced seeds) add certain "don't care" positions to k-mers to allow them to be tolerant to mismatches, but they are still highly affected by short insertions and deletions (indels).

Recently, the idea of ["strobemers" has been introduced](https://genome.cshlp.org/content/early/2021/10/19/gr.275648.121.full.pdf), and a lightweight aligner has even been [built around this idea](https://genomebiology.biomedcentral.com/articles/10.1186/s13059-022-02831-7).  Even more recently, the tool ["X-Mapper"](https://genomebiology.biomedcentral.com/articles/10.1186/s13059-024-03473-7) has been published, which introduces the idea of "gapped x-mers".  

In general, there are many types of seeds that can be used for sequence alignment, with the limiting factor essentially being the creativity of the authors coming up with the ideas, and the ability of different data structures to support efficiently indexing these seeds. The goal of this project it to work to improve the properties of these seeds or to create your own new strategy for deriving indel-tolerant seeds. The scope of this project is also largely up to you.  That is, you are not restricted simply to designing a better strobemer, or gapped x-mer, but instead are invited to explore more generally different types of seeds and how effective they might be at aiding in the initial phase of alignment.

### 8) Comparison of different ways of estimating the uncertainty associated with transcript quantification and its impact on downstream analysis for RNA-Seq

Genes can express multiple transcripts due to a phenomenon called alternative splicing and as a result many transcripts contain overlapping sequences due to the presence of shared exons. The sequenced fragments obtained during RNA-Seq represent subsequences of the transcripts and these can belong to the shared sequence regions between the transcripts. Thus, when the reads are mapped back to the transcriptome, we do not know their true locus of origin. An approach that has been employed to solve this problem is to probabilistically assign the reads to the transcripts in the tools such as [RSEM](https://github.com/deweylab/RSEM), [Kallisto](https://github.com/pachterlab/kallisto) and [Salmon](https://github.com/COMBINE-lab/salmon), which provide a point estimate as an output for transcript abundance. However, there exists uncertainty in estimating the abundance estimates due to the reasons mentioned above.

The above mentioned tools also provide the options to generate additional samples called inferential replicates for each RNA-Seq sample, through approaches such as boostrap sampling and Gibbs Sampling. The output can be thought of as $N$ X $K$ matrix $M$, where $N$ is the total number of transcripts and $K$ are the number of inferential replicates, with $M_{nk}$ denoting the transcript counts obtained on the transcript $n$ for the inferential replicate $k$. The inferential replicates can be used to estimate the uncertainty associated with quantification. 

Among the first goals of the projects is to come up with quantitative and qualitative strategies to compare the performance of these two approaches in capturing the uncertainty associated with transcript quantification. One starting point would be to compare the coverage interval as shown in the [ISOEM2](https://academic.oup.com/bioinformatics/article/33/20/3302/3866474) paper. The second part of the project would be to come up with an alternative strategy of exploring the posterior distribution. One such way would be to implement a more sophisticated and efficient posterior sampling strategy than the Gibbs sampler that is commonly used — a method like Hamiltonian Monte Carlo, or the No U-Turn Sampler (NUTS). Another such way could be to think about possible variations in the bootstrap strategy. The performance of these methods should also be compared w.r.t downstream tasks that make use of inferential replicates. The examples of these tasks include differential testing methods such as ([edgeR](https://rdrr.io/bioc/edgeR/man/catchSalmon.html), and [swish](https://github.com/thelovelab/fishpond)) and methods that organize transcripts into a tree ([TreeTerminus](https://github.com/COMBINE-lab/treeterminus)).    

### 9) Improving the tree generating mechanism in TreeTerminus and exploring different strategies for constructing consensus trees

When analyzing the transcriptomic data, there usually exist two resolution levels for analysis. While transcripts provide the finest resolution, a certain degree of uncertainty is always associated with their abundance estimates. Conversely, gene-level analysis, though less ambiguous, can be too coarse-grained. An alternative is to group transcripts into discrete groups and use it as the feature for analysis, as done in [Terminus](https://academic.oup.com/bioinformatics/article/36/Supplement_1/i102/5870485?login=true). We recently published [TreeTerminus](https://www.cell.com/iscience/fulltext/S2589-0042(23)01038-6), that expands upon Terminus and groups transcripts into a tree structure where leaves represent individual transcripts and internal nodes represent an aggregation of a transcript set. TreeTerminus constructs trees such that, on average, the inferential uncertainty decreases as we ascend the tree topology.

For a single RNA-Seq sample, TreeTerminus makes use of equivalence classes and the inferential replicates (generated either though bootstrapping or Gibbs Sampling) for constructing the trees. The equivalence classes is a relation from the set of reads to set of transcripts, such that all reads in an equivalence class map to the same set of transcripts. Remember, reads can map equally well to multiple transcripts, as they share common sequences due to alternative splicing. This is the major reason that there exists uncertainty when estimating the transcript abundances.

Goal : When creating transcript-trees for a single RNA-Seq sample, TreeTerminus uses an iterative greedy procedure to construct binary trees. It selects the pair of transcripts such that grouping them leads to the largest reduction in uncertainty compared to any other pair and creates a binary tree. This process continues iteratively till the time a stopping criterion is reached and at the end a forest of binary tree of transcripts is produced. We want you to extend the functionality of TreeTerminus such that it can construct multi-ary trees. This is specifically useful for the set of transcripts that appear in exactly the same set of equivalence classes and have near-identical conditional probability vectors. Currently, TreeTerminus randomly picks a pair of transcripts from this set for creating a binary tree. We provide two modes (Mean and Consensus) to constructs the trees across samples for an RNA-Seq experiment. We want you to compare how the Mean and Consensus trees change after multi-ary trees are constructed for a single sample. Some of the starting metrics for comparison could include the Robinson-Fould distance and the differences in the groups and optimal values obtained after optimizing for the objective function on the tree (as defined in the paper). We though would like to see other types of comparisons (both qualitative and quantitative) with respect to the trees. In the second part of the project, we want to you to come up with approaches to improve the memory footprint of the procedure that generates the Mean tree. Currently, it requires loading all the samples along with their inferential replicates into memory, which might not be scalable for large RNA-Seq experiments. (Also has the scope for comparison with different consensus procedures though I have not added them) .

## 10) Speeding up parallel suffix array construction with smart memoization of LCPs

String indexes such as the suffix array (SA) and the closely related longest common prefix (LCP) array are fundamental objects in bioinformatics and have a wide variety of applications. Despite their importance in practice, few scalable parallel algorithms for constructing these are known, and the existing algorithms can be highly non-trivial to implement and parallelize. Recently, Khan et al. (2023) introduced `CaPS-SA`, a simple and scalable parallel algorithm for constructing these string indexes inspired by samplesort. `CaPS-SA` outperforms existing state-of-the-art parallel SA and LCP-array construction algorithms on modern hardware.

A potential downside of the algorithm is that it is _output-sensitive_ and as a result its worst-case time complexity on adversarial inputs is quadratic. However, in practice we find that the shared-memory implementation of `CaPS-SA` outperforms state-of-the-art methods in terms of runtime and scalability. For highly repetitive inputs however, e.g. collections of genome from the same species, the cost factor associated to the output-sensitivity becomes quite significant. Specifically, the complexity of the algorithm is $O(n \log n + \sum_i L_i)$, where $L_i$ is the output LCP-array.

The goal is to update the algorithm in such a way that the $\sum L_i$ factor can be cut down by some non-trivial factor (optimally, _eliminated_). This may be achievable through intelligent _memoization_, _subsampling_, and similar constructs over the LCP-function `LCP(i, j)`. The target is to try out these ideas to rectify the time-complexity of the algorithm and the associated implementation. The lead author (and primary implementer) of the `CaPS-SA` algorithm is a PhD student in Rob's lab, and would be available to chat with or give advice to a group choosing this project.

Fun fact: the mentioned algorithm and paper culminated directly from a class project in another course.
